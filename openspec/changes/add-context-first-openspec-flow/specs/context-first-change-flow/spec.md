## Purpose

Задаёт проверяемый путь от сырой идеи и продуктового контекста до согласованного OpenSpec Change без преждевременной реализации и выдуманных фактов.

## ADDED Requirements

### Requirement: Flow начинается с подтверждённого контекста
Перед вопросами и созданием OpenSpec-артефактов flow MUST прочитать `CONTEXT.md`, `product.yaml`, `services.lock.yaml`, правила репозитория и релевантные действующие спецификации. Утверждения о сервисе MUST проверяться на полном SHA из lock-файла; отсутствующие факты MUST оставаться вопросами, а не допущениями.

#### Scenario: Подготовка изменения продукта
- **WHEN** пользователь просит подготовить изменение кредитного калькулятора
- **THEN** flow сначала сверяет запрос с доменным словарём, границами продукта и закреплённой версией сервиса

#### Scenario: Факт отсутствует в разрешённых источниках
- **WHEN** для решения нет подтверждения в контексте, спецификации или закреплённом сервисе
- **THEN** flow фиксирует неизвестное и запрашивает предметное решение вместо генерации факта

### Requirement: MTP grilling предшествует OpenSpec Propose
Flow SHALL использовать MTP `grill-with-docs` для изменений, затрагивающих доменный язык или долгоживущие решения, и SHALL использовать `grill-me` для ограниченного обсуждения без изменения доменных документов. Интервью MUST продолжаться по дереву решений до явного подтверждения общего понимания.

#### Scenario: Изменение вводит новый предметный термин
- **WHEN** запрос меняет язык предметной области или выявляет неоднозначный термин
- **THEN** flow запускает `grill-with-docs`, а `domain-modeling` обновляет только словарь и обоснованные ADR

#### Scenario: Изменение не затрагивает доменную модель
- **WHEN** вопрос ограничен планом или дизайном и не меняет общий язык проекта
- **THEN** flow может использовать `grill-me`, сохраняя тот же обязательный gate общего понимания

### Requirement: Explore является условной стадией
После завершённого grill flow SHALL запускать OpenSpec Explore только при наличии нерешённой продуктовой, архитектурной или проверочной развилки. Если существенных развилок нет, flow MUST переходить непосредственно к OpenSpec Propose.

#### Scenario: Осталась архитектурная развилка
- **WHEN** два допустимых решения имеют разные внешние последствия или критерии приёмки
- **THEN** flow исследует варианты в OpenSpec Explore и не создаёт proposal до решения развилки

#### Scenario: Все развилки закрыты
- **WHEN** дерево решений завершено и входы спецификации однозначны
- **THEN** flow пропускает Explore как лишний этап

### Requirement: Propose создаёт только планирующие артефакты
OpenSpec Propose MUST создать полный набор артефактов, требуемый выбранной схемой, и MUST NOT автоматически запускать Apply или менять код сервиса. Перед Apply человек MUST принять границы, требования, дизайн, задачи и условия проверки.

#### Scenario: Proposal готов
- **WHEN** OpenSpec validation подтверждает полный набор proposal, delta specs, design и tasks
- **THEN** flow останавливается на человеческой проверке и предлагает отдельный запуск Apply

### Requirement: Поднабор MTP воспроизводим и атрибутирован
Репозиторий MUST хранить необходимый поднабор MTP skills вместе с исходным repository URL, закреплённым полным commit SHA, MIT-атрибуцией и всеми файлами, необходимыми их зависимостям. `prototype` MUST оставаться самостоятельным устанавливаемым skill. Обновление upstream-версии MUST быть явным проверяемым изменением.

#### Scenario: Проверка происхождения skills
- **WHEN** выполняется gate метарепозитория
- **THEN** он подтверждает наличие ожидаемых skills, включая standalone `prototype`, их provenance manifest, лицензию и закреплённый upstream SHA

#### Scenario: Коробочная установка закреплённой версии
- **WHEN** участник выполняет `npm run skills:install`
- **THEN** команда воспроизводимо устанавливает project-local MTP skills из SHA provenance manifest и подтверждает их хэши

#### Scenario: Явное обновление MTP
- **WHEN** сопровождающий выполняет `npm run skills:update -- <full-sha>`
- **THEN** команда отклоняет неполный SHA, обновляет skills и provenance manifest одним проверяемым diff и не затрагивает локальные product-specific skills

### Requirement: Flow сохраняет границы данных
Flow MUST NOT помещать в OpenSpec, доменные документы или Git секреты, персональные данные, корпоративные документы и содержимое `.workspace/`. Локальный privacy scan MUST проверять новые артефакты до человеческой приёмки.

#### Scenario: Материал не разрешён для публикации
- **WHEN** источник содержит секрет, персональные сведения или непубличный корпоративный контекст
- **THEN** flow останавливает перенос данных и запрашивает защищённое хранилище или безопасную ссылку вместо включения содержимого в Git
