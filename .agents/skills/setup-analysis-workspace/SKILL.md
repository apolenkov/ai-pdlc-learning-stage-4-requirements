# Настройка рабочей среды анализа

Развернуть синтетическую учебную среду через контракт самого метарепозитория. Считать `package.json`, lock-файлы и команды репозитория единственным источником истины.

## Выполнить

1. Найти корень выбранного метарепозитория и прочитать действующие `AGENTS.md`, `README.md`, `package.json` и lock-файлы.
2. Убедиться, что пользователь выбрал учебный или явно разрешённый репозиторий. Остановиться, если для продолжения нужны ключи, рабочие корпоративные данные, неизвестный URL или незакреплённая версия.
3. Проверить наличие скрипта `setup` в `package.json`. Если его нет, сообщить: «Шаблон не поддерживает автоматическую настройку; используйте ручной путь из README».
4. Проверить `git status --porcelain=v1 --untracked-files=all`. При любых изменениях остановиться до `npm ci`: использовать чистую копию либо попросить владельца шаблона сохранить работу.
5. Выполнить `npm ci`, затем один раз `npm run setup`. Не переносить внутренние команды `setup` в этот skill.
6. Прочитать Store ID из `.openspec-store/store.yaml`. Если файл отсутствует или identity некорректна, остановиться и не создавать её автоматически. Получить канонический физический путь корня через `pwd -P` или эквивалент ОС и выполнить `npm exec openspec -- store list --json`.
7. Если Store ID ещё не зарегистрирован, выполнить `npm exec openspec -- store register . --yes --json`. Если он уже указывает на тот же физический путь, ничего не менять. Если прежнего пути больше не существует, выполнить `npm exec openspec -- store unregister <Store ID> --json`, затем зарегистрировать текущий корень. Если ID указывает на другой существующий checkout, остановиться и показать оба пути.
8. Выполнить `npm exec openspec -- store doctor <Store ID> --json`. При любой ошибке остановиться, не подменяя Store и не меняя его identity.
9. Снова получить Git status. Любая новая запись означает ошибку настройки.
10. Сообщить результаты `setup`, закреплённый SHA сервиса, Store ID, результат doctor и следующий учебный шаг из README. Долгоживущий сервер автоматически не запускать.

## Остановиться безопасно

- При первой ошибке прекратить последующие команды и привести последнюю понятную строку ошибки.
- Не запрашивать и не выводить секреты. Не добавлять `.env`, токены или ключи в файлы проекта.
- Не менять URL, SHA и lock-файлы ради успешного запуска.
- Если Store ID связан с другим существующим checkout, не предлагать пользователю варианты и не переключать регистрацию автоматически. Остановиться с точными путями: выбор рабочего checkout делает владелец среды.
- Не выполнять commit, push, публикацию и записи во внешние системы.

## Готово, если

- `npm run setup` завершился с PASS;
- закреплённые URL и SHA проверены командами метарепозитория;
- Store указывает на текущий checkout, а doctor не сообщает проблем;
- Git status после настройки остаётся пустым;
- пользователь получил один следующий шаг: провести интервью через `grill-with-docs`.
