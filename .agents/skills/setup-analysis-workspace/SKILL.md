# Подготовка среды анализа

Работайте в выбранном метарепозитории. Прочитайте AGENTS.md, README.md и package.json; команды берите из package.json.

1. Проверьте `git status --porcelain=v1 --untracked-files=all`. Если есть правки, остановитесь и покажите список файлов. Не сбрасывайте и не коммитьте чужую работу.
2. Выполните `npm ci`, затем один раз `npm run setup`. При ошибке остановитесь и сообщите причину; не меняйте зависимости и lock-файлы ради успешной проверки.
3. Повторите Git status. Успех означает: обе команды завершились с кодом 0 и status остался пустым.
4. Сообщите результаты организатору. Затем следуйте `docs/organizer-stage-4.md`: импортируйте личный baseline и весь активный Change по полному SHA, подготовьте personal base и отдельно проверьте регистрацию Store без автоматической замены конфликтующего root.
5. Перед передачей среды выполните два `npm run bootstrap` в чистой personal base и проверки из CONTRIBUTING.md. Этот skill сам по себе не подтверждает доступность OpenCode или модели. В готовой среде аналитик начинает с `npm run bootstrap`, затем запускает `opencode` из того же корня и обсуждает идею через original project skill `grill-with-docs`.

Первичная setup-проверка относится только к Store: не получает сервис, не запускает сервер и не меняет реестр OpenSpec. Импорт, регистрация и bootstrap остаются отдельными организаторскими действиями и не входят в автоматические действия этого skill.

Не выполняйте commit, push, публикацию или записи в Jira. Не запрашивайте и не выводите секреты. Если отсутствует обязательный доступ, объясните, какой шаг не удалось проверить.
