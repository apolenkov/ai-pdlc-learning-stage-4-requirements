# Настройка рабочей среды анализа

Развернуть синтетическую учебную среду через контракт самого метарепозитория. Считать `package.json`, lock-файлы и команды репозитория единственным источником истины.

## Выполнить

1. Найти корень выбранного метарепозитория и прочитать действующие `AGENTS.md`, `README.md`, `package.json` и lock-файлы.
2. Убедиться, что пользователь выбрал учебный или явно разрешённый репозиторий. Остановиться, если для продолжения нужны ключи, рабочие корпоративные данные, неизвестный URL или незакреплённая версия.
3. Проверить наличие скрипта `setup` в `package.json`. Если его нет, сообщить: «Шаблон не поддерживает автоматическую настройку; используйте ручной путь из README».
4. Проверить `git status --porcelain=v1 --untracked-files=all`. При любых изменениях остановиться до `npm ci`: использовать чистую копию либо попросить владельца шаблона сохранить работу.
5. Выполнить `npm ci`, затем дважды `npm run setup`. Не переносить команды из `setup` в этот skill.
6. Снова получить Git status. Любая новая запись означает ошибку настройки.
7. Сообщить результаты фаз `preflight`, `setup`, `verify`, закреплённый SHA сервиса и следующую команду из README. Долгоживущий сервер автоматически не запускать.

## Остановиться безопасно

- При первой ошибке прекратить последующие команды и привести последнюю понятную строку ошибки.
- Не запрашивать и не выводить секреты. Не добавлять `.env`, токены или ключи в файлы проекта.
- Не менять URL, SHA и lock-файлы ради успешного запуска.
- Не выполнять commit, push, публикацию и записи во внешние системы.

## Готово, если

- оба запуска `npm run setup` завершились с PASS;
- закреплённые URL и SHA проверены командами метарепозитория;
- Git status после настройки остаётся пустым;
- пользователь получил одну следующую команду для ручного запуска учебного сервиса.
