# Сопровождение метарепозитория

## Проверка содержимого Store

Из корня:

```bash
npm ci
npm run setup
git status --short
```

setup запускает doctor и check. Сервисный checkout и регистрация Store не нужны. После изменения файлов достаточно npm run check; чистота Git требуется при проверке установки из новой копии, а не во время редактирования.

check проверяет типы, собственные тесты, provenance skills, OpenSpec и отсутствие запрещённых публикуемых данных. Успех этой команды не доказывает работоспособность сервиса.

## Получение исходников для анализа

Необязательная команда:

```bash
npm run bootstrap
```

Она получает исходники на версии из services.lock.yaml без установки зависимостей сервиса. При другом origin, SHA или локальных правках существующий snapshot не перезаписывается. Не разрабатывайте в .workspace.

Тесты и запуск сервиса выполняйте в отдельном рабочем клоне по его README.

## Обновление skills

MTP grill-with-docs и его зависимости закреплены в .agents/mtp-skills.lock.json. Проверка npm run skills:check уже входит в check.

Обновление через npm run skills:update требует отдельного решения о версии и полного commit SHA. Не выбирайте его автоматически. Проверьте diff и provenance. MTP to-spec не используется: требования ведутся в OpenSpec.

Официальные OpenSpec workflows в .opencode/skills обновляйте штатными средствами OpenSpec, не редактируйте их вручную.

## Реестр Store и временные проверки

Регистрация нужна при работе со Store из другого репозитория. Сначала проверьте текущую регистрацию; при конфликте покажите оба пути, не переключайте её автоматически.

Временный acceptance-checkout не регистрируйте в пользовательском реестре. Если проверяете Store-команды, используйте отдельный временный XDG_DATA_HOME. Сохраните результаты команд и убедитесь, что основной реестр не изменился.

Схемы владения требованиями и отдельный маршрут реализации находятся в [архитектуре](docs/architecture/openspec-store-workset.md).
