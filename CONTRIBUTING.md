# Сопровождение метарепозитория

Общая `main` — универсальный эталон R4, а не готовая личная история ученика. Изменяйте её через maintenance-ветку и review. Personal import-base готовится отдельно по [инструкции организатора](docs/organizer-stage-4.md), публикуется отдельной веткой и не сливается обратно как учебный результат.

## Граница ролей

- Организатор получает полный SHA планирования ученика, переносит из его Git tree весь `openspec/specs/` и все активные Changes, формирует manifest, проверяет отдельный service pin и публикует personal import-base.
- Ученик сам клонирует опубликованную ветку в папку `sdd-credit-calculator-product-meta-example`, запускает OpenCode и вызывает `setup-analysis-workspace`.
- Setup skill выполняет только `npm ci` и `npm run setup` с чистым status до и после.
- Регистрация Store требует отдельной проверки root. Отсутствующая запись создаётся только после явного разрешения организатора; конфликтующий root не заменяется автоматически.
- После правильной регистрации ученик выполняет два реальных bootstrap и продолжает аналитический маршрут из README.

R3-ИИ необязательна: manifest может содержать один или несколько импортированных Changes. Main specs источника могут быть пусты. Не добавляйте фиктивный baseline и не закрепляйте SHA планирования в `services.lock.yaml`.

## Проверка эталона

Перед commit выполните:

```bash
npm run check
git diff --check
git diff
git status --short
```

Тесты должны проверять source-driven inventory и инварианты, а не фиксированное число Changes, файлов, строк матрицы или вхождений текста. Отдельно различайте fixture-тесты и реальные bootstrap подготовленной personal base.

MTP `grill-with-docs` и зависимости закреплены в `.agents/mtp-skills.lock.json`. Не редактируйте оригинальные MTP и сгенерированные OpenSpec skills вручную. Обновление MTP через `npm run skills:update` требует отдельного решения о версии и полном SHA.

Подготовка, публикация ветки, planning PR, человеческие review и будущий Apply — разные действия. Локальная проверка не подтверждает публикацию, реализацию функций или человеческую приёмку.
