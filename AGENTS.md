# Правила метарепозитория

- Репозиторий хранит контекст продукта и спецификации, но не код сервиса.
- Перед изменением спецификации проверьте `CONTEXT.md`, `product.yaml` и `services.lock.yaml`.
- Не придумывайте отсутствующие факты: задайте предметные вопросы и зафиксируйте ответ.
- Любое утверждение о сервисе проверяйте на закреплённом полном Git SHA.
- Не добавляйте токены, персональные данные, корпоративные документы или локальную `.workspace/`.
- Для изменений используйте `npm run check`; результат принимает человек.

## Подготовка OpenSpec Change

1. Прочитайте `CONTEXT.md`, `product.yaml`, `services.lock.yaml`, `docs/agents/domain.md` и релевантные действующие спецификации. Неподтверждённые факты оставляйте вопросами.
2. Используйте оригинальный MTP `grill-with-docs` для доменных или долгоживущих решений; для ограниченного обсуждения без изменения доменных документов допустим `grill-me`. Продолжайте до явного подтверждения общего понимания.
3. Если после grill остаётся существенная развилка, используйте OpenSpec Explore; иначе переходите к OpenSpec Propose.
4. OpenSpec Propose должен создать полный planning-набор выбранной схемы и остановиться на человеческой проверке. Apply запускается отдельно только после принятия границ, требований, дизайна, задач и проверок.

OpenSpec — единственный источник спецификации. MTP `to-spec` не используется. Не создавайте локальный process skill, пересказывающий MTP или OpenSpec.

## Настройка учебной среды

- Канонический skill `.agents/skills/setup-analysis-workspace` входит в шаблон метарепозитория и вызывает только его публичный контракт `npm run setup`.
- Не переносите команды из `scripts/setup.ts` в skill: настройка должна оставаться проверяемой и без ИИ.
- Глобальная копия skill — установленный экземпляр для конкретного компьютера, а не источник истины.
