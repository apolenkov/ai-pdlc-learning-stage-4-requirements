# Правила метарепозитория

- Учебную работу ведите в персональной ветке. Не отправляйте её напрямую и не сливайте в общую main эталона; после review сохраните ветку и закройте учебный PR без слияния. Сопровождение эталона владельцем — отдельная задача.

- Репозиторий хранит контекст продукта и спецификации, но не код сервиса.
- Перед изменением прочитайте `CONTEXT.md`, `product.yaml`,
  `services.lock.yaml`, `docs/course/stage-3-transfer.md`, действующие
  спецификации и весь унаследованный активный Change.
- Не придумывайте отсутствующие факты: оставляйте их открытыми вопросами.
- Полный SHA из `services.lock.yaml` — база проверки, а не вход задачи или
  реализации.
- Не добавляйте токены, персональные данные, корпоративные документы или
  локальную `.workspace/`.
- Изменения должны пройти `npm run check` и человеческую проверку.

## Подготовка OpenSpec Change

1. Используйте оригинальный MTP `grill-with-docs` и продолжайте интервью до
   явного подтверждения общего понимания.
2. Если после grill остаётся существенная развилка, используйте OpenSpec Explore; иначе переходите к OpenSpec Propose.
3. OpenSpec Propose создаёт полный planning-набор выбранной схемы и останавливается на человеческой проверке.
4. Apply запускается отдельно только после принятия границ, требований,
   дизайна, задач и проверок.

На ступени 4 новый `limit-credit-amount` обязан явно зависеть от активного
`add-reset-and-years-term`. Все задачи реализации обоих Changes остаются
незавершёнными до отдельного Apply. Автоматическая проверка и ИИ не заменяют
два последовательных человеческих review актуального diff.
Унаследованный Change сохраняет ввод целого срока в месяцах, добавляет
переключатель «месяцы / годы», перевод лет в целые месяцы и reset в обоих
режимах без автоматического расчёта.

OpenSpec — единственный источник спецификации. MTP `to-spec` не используется.
Не создавайте локальный process skill, пересказывающий MTP или OpenSpec.

## Store и реализация

- Этот репозиторий — Store `sdd-credit-calculator-product-meta`; identity
  хранится в `.openspec-store/store.yaml`.
- Для чтения, validation и будущего Apply указывайте явный
  `--store sdd-credit-calculator-product-meta` и сначала подтверждайте root.
- Store владеет общей спецификацией и Change. Репозиторий сервиса владеет
  кодом, тестами и своей Git-историей.
- Для Apply используйте Store и отдельный рабочий клон сервиса; Workset необязателен.
  `.workspace/services/credit-calculator` — только проверочный снимок.
- В обычном продуктовом процессе после merge service PR обновите
  `services.lock.yaml` итоговым SHA в Store PR, проверьте свежий чистый клон
  и архивируйте Change. Учебная ветка ниже до этого этапа не доходит.
- Store и Workset не выполняют Git clone, pull, push или merge.
- Самостоятельная ступень 3 остаётся repo-local. Переход к Store-only выполняется
  только в отдельной учебной ветке после проверки сохранности требований и истории.
  Не сливайте смену ownership в общую main учебного шаблона.
- Личная R3-ветка после импорта — исторический источник. В personal base R4
  Store становится единственным активным владельцем baseline и обоих Changes;
  не поддерживайте вторую редактируемую planning-копию.

## Настройка среды

- Канонический `.agents/skills/setup-analysis-workspace` выполняет
  `npm ci` и один раз `npm run setup`, проверяя чистоту Git до и после.
  Импорт личного R3-контракта и регистрация Store выполняются организатором
  отдельно по `docs/organizer-stage-4.md`, до передачи папки аналитику.
- Только при отдельной регистрации Store: если ID указывает на другой
  существующий checkout, остановитесь и покажите оба пути. Не переключайте
  регистрацию автоматически; обычный setup её не проверяет и не меняет.
- Временные acceptance-checkout запускают Store-команды только с отдельным временным `XDG_DATA_HOME`. Не регистрируйте временный checkout в пользовательском реестре OpenSpec.
- Не переносите внутренние команды setup в skill.
- Аналитик начинает только с `npm run bootstrap`, затем `opencode`. Bootstrap
  проверяет чистый meta checkout, ожидаемый Store root, закреплённый snapshot,
  точный inventory и байты импортированного baseline и всего Change;
  он не исправляет и не перерегистрирует чужое состояние.
