# Ступень 3★. От идеи до проверенного OpenSpec Change

Здесь аналитик уточняет идею, готовит изменение требований и передаёт его на review. Результат — согласованный OpenSpec Change; код сервиса на этой ступени не меняется.

Нужны Git, Node.js 22+, npm, OpenCode с корпоративной моделью и доступ к учебным Jira и GitHub. Новая структура пока подготовлена локально; до публикации удалённая main может отличаться от этого маршрута.

## 1. Клонируйте репозиторий и подготовьте среду

```bash
git clone https://github.com/apolenkov/sdd-guide-credit-calculator-stage-4-requirements.git
cd sdd-credit-calculator-product-meta-example
git switch -c feature/limit-credit-amount
opencode
```

В OpenCode выберите режим Build и корпоративную модель. Скопируйте сообщение:

```text
Загрузи project skill setup-analysis-workspace через инструмент skill
и выполни его для текущего метарепозитория.
После проверки сообщи результаты команд и git status.
Не создавай Change и не меняй файлы проекта.
```

Skill входит в репозиторий. Он выполняет npm ci и npm run setup, не получает сервис и не регистрирует Store. Если skill не обнаружен, попросите агента прочитать .agents/skills/setup-analysis-workspace/SKILL.md и следовать этому файлу.

Продолжайте, только если команды завершились успешно и Git status пуст. Внутренние команды setup повторять не нужно.

## 2. Создайте учебную задачу

Если задача уже выдана, используйте её. Иначе создайте в Jira Task проекта DEMO с родителем `DEMO-1 · учебный эпик курса` Если эпик недоступен, уточните актуального родителя у организатора обучения.

Название: «Ограничить допустимую сумму кредита в учебном калькуляторе».

Описание для копирования:

```text
Учебная цель: уточнить идею, подготовить OpenSpec Change
и передать его на review без изменения кода сервиса.

Разрешить сумму кредита от 10 000 до 100 000 000 ₽ включительно.
Если сумма вне диапазона, показать ошибку и не выводить новый результат.

Технический идентификатор Change и ветки: limit-credit-amount.
Неуточнённые детали выявляем на интервью.
Результат задачи: ссылка на PR с проверенным Change.
```

Jira хранит цель и ссылки на результат. Требования ведутся в OpenSpec; переписывать их в комментарии Jira не нужно.

## 3. Обсудите идею с агентом

В той же сессии OpenCode отправьте:

```text
Используй project skill grill-with-docs. Обсудим идею:
разрешить сумму кредита от 10 000 до 100 000 000 ₽ включительно.
Если сумма вне диапазона, показать ошибку и не выводить новый результат.

Сопоставь идею с CONTEXT.md, product.yaml, services.lock.yaml
и openspec/specs/credit-calculator/spec.md.
Задавай вопросы раундами до общего понимания. Уточни границы,
дробные значения, поведение предыдущего результата и проверку ошибки.
Не придумывай ответы за меня. Код и документы пока не меняй,
OpenSpec Change не создавай.
В конце подведи итоги и отдельно перечисли оставшиеся вопросы.
```

Отвечайте на вопросы и проверьте итог. Если нужен анализ реализации, отдельно попросите получить исходники через npm run bootstrap. Это необязательный снимок для чтения, не рабочая ветка.

Не копируйте заранее придуманный список решений из чужой сессии. Подтвердите только те решения, которые действительно согласовали. Итог остаётся в сессии, затем переносится в Change.

## 4. Разберите развилку, если она осталась

Если решение влияет на поведение, архитектуру или проверку и ещё не принято, отправьте:

```text
Используй OpenSpec Explore. Разбери оставшиеся вопросы из итогов
нашего интервью: варианты, последствия и рекомендуемое решение.
Опирайся на документы проекта. Не меняй код и не создавай Change.
Задай вопросы, ответы на которые нужны для выбора.
```

Если существенных вопросов нет, пропустите этот шаг. После Explore подтвердите обновлённое понимание в той же сессии.

## 5. Подготовьте Change

После подтверждения итогов скопируйте:

```text
Используй OpenSpec Propose для limit-credit-amount.
По подтверждённым итогам нашего интервью создай полный набор
схемы spec-driven: proposal, delta specs, design и tasks.
Укажи credit-calculator в Modified Capabilities: меняются требования
существующей возможности.
Опиши диапазон суммы и согласованное поведение ошибки,
сохрани остальные действующие требования и сценарии.
Задачи должны содержать способ проверки результата.
Не реализуй изменение и не меняй services.lock.yaml. Проверь Change строгой валидацией
и остановись для человеческого review.
```

Читайте файлы в openspec/changes/limit-credit-amount. Proposal объясняет причину и объём; delta specs — изменения требований; design — способ реализации; tasks — действия и проверки. Они должны отражать ваше интервью, а не пример чужих ответов.

## 6. Проверьте и передайте результат

Для предварительного review отправьте:

```text
Проведи критическое review Change limit-credit-amount.
Сверь proposal, delta specs, design и tasks с действующей
спецификацией и подтверждёнными итогами интервью.
Найди противоречия, потерянные сценарии, непроверяемые требования
и лишние действия. Для каждого замечания укажи файл и причину.
Ничего не исправляй без обсуждения. Код не реализуй.
```

Обсудите замечания и исправьте принятые. Затем выполните из корня:

```bash
npm exec openspec -- validate limit-credit-amount --strict
npm run check
git diff --check
git diff
git status --short
```

Проверьте также новые файлы: обычный git diff не показывает их содержимое. Сохраняйте только Change:

```bash
git add openspec/changes/limit-credit-amount
git diff --cached
git commit -m "docs: propose credit amount limits"
git push -u origin feature/limit-credit-amount
```

Откройте PR в main. Другой аналитик проверяет требования, разработчик или архитектор — реализуемость и проверки. ИИ-review не заменяет эти подтверждения. Исправьте замечания; после правок проверяющие должны подтвердить актуальную версию. В Jira добавьте ссылку на PR.

Ступень завершена после человеческого review и устранения блокирующих замечаний. Change ещё не реализован: не отмечайте tasks выполненными и не архивируйте его.

## Что где хранится

| Место | Ответственность |
| --- | --- |
| CONTEXT.md | Термины предметной области |
| product.yaml | Описание продукта и ссылки на его контекст |
| services.lock.yaml | Проверенная версия исходников для анализа |
| openspec/specs | Действующие требования |
| openspec/changes | Планируемые изменения и история |
| .workspace | Необязательный снимок сервиса, только для чтения |

Продолжение с реализацией — отдельный маршрут в [архитектуре Store и Workset](docs/architecture/openspec-store-workset.md). Самостоятельный пример ступени 3 использует repo-local OpenSpec. Не переводите его общую main в Store-only ради одного упражнения.

Для продолжения в OpenCode Web выберите прежнюю сессию проекта. В терминальном OpenCode команда `/sessions` открывает список сессий, а `opencode --continue` из корня проекта продолжает последнюю. Если начинаете новую, передайте файлы Change и подтверждённые итоги интервью; не рассчитывайте, что агент помнит другой чат.

[Сопровождение шаблона](CONTRIBUTING.md) не требуется для прохождения упражнения.
