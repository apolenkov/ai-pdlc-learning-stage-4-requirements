# Запросы и замыслы кредитного калькулятора

Место в курсе: подготовка → шаг 1 «Требования в Git» → шаг 2 «Проверяем и согласуем» → шаг 3 «Изменение в OpenSpec» (обязательный) → шаги 4–5 «Команда продукта» и «Контекст продукта» → 6а или 6б → «Практикум разработки».

## Один запрос для шагов 1–3

- `../request-and-answers.md` — исходное обращение и подтверждённые ответы; это источник фактов упражнения.
- `../intent-template.md` — общий шаблон на понятном языке.
- `../examples/clear-calculation-result.md` — предоставленный пример разбора, не вторая версия фактов и не личный документ ученика.
- `intent-1-error-result.md` — старый адрес, сохранённый для ссылок; он ведёт к примеру.

В личной рабочей ветке ученик создаёт один `intents/clear-calculation-result.md` и меняет его при уточнении запроса. Этот файл, а не предоставленный пример из учебного репозитория, становится актуальным изложением потребности в его истории Git. В импортированной истории R4 источник и полный SHA сохраняются в `docs/course/planning-provenance.json` и read-only снимке `.workspace/planning/stage-3`.

## Отдельный запрос шагов 4–5

`intent-2-credit-limit.md` — стартовый пример новой потребности: получить допустимый предел суммы из системы банка. В личной ветке это один рабочий документ R4; уточняйте его после подтверждения ответов и не создавайте копии по шагам. Открытые вопросы остаются вопросами, пока их не подтвердили. Этот запрос не является следующей частью предыдущего. В примере шаги 4–5 затрагивают интеграцию систем, поэтому архитектора приглашают через @; одобряет по-прежнему владелец продукта.

## Как документ проходит работу

Исходное обращение и подтверждённые ответы помогают сформулировать потребность. Неизвестное остаётся вопросом. Инициатор подтверждает смысл, владелец решения принимает его; аналитик помогает уточнить формулировку. Требования развивают подтверждённый замысел, а Git сохраняет изменения и позволяет показать, из какой версии они выросли.
