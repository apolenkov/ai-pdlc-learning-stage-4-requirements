# Запросы и замыслы кредитного калькулятора

Полный курс идёт так: Введение → R1 → R2 → обязательные SDD и OpenSpec → R4. R3 — факультативная ручная практика.

## Один запрос для R1–R3

- `../request-and-answers.md` — исходное обращение и подтверждённые ответы.
- `../intent-template.md` — общий шаблон на понятном языке.
- `clear-calculation-result.md` — один согласованный учебный пример, который связывает ошибку ввода, сброс и срок в годах.
- `intent-1-error-result.md` — оставленный для старых ссылок адрес; отдельный intent для R1, R2 и R3 не нужен.

В рабочем маршруте ученик формулирует один документ `intents/clear-calculation-result.md` и ведёт его историю в Git. Потребность и её уточнения остаются доступным контекстом людям и языковой модели. В будущем метарепозиторий сможет связывать такой контекст с требованиями, архитектурой и кодом.

## Отдельный запрос R4

`intent-2-credit-limit.md` описывает новый запрос: получить допустимый предел суммы из системы банка. Это самостоятельное изменение с собственными открытыми вопросами; оно не является следующей частью предыдущего intent. Для этого примера R4 затрагивает интеграцию систем, поэтому архитектор участвует в проверке.

## Как документ проходит работу

Исходное обращение и подтверждённые ответы помогают сформулировать потребность. Неизвестное остаётся вопросом. Инициатор подтверждает смысл, владелец решения принимает его; аналитик помогает уточнить формулировку. Требования развивают подтверждённый замысел, а Git сохраняет изменения и позволяет показать, из какой версии они выросли.
